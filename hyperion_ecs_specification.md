# System Specification: Hyperion ECS (Agent Execution Target)

## Document Control & Constraints
* **Project Name:** Hyperion ECS
* **Target Platform:** Java 25 (OpenJDK 25 / LTS). *(Migrated from Java 21 — see ADR-0008. On JDK 25 the Foreign Function & Memory API is final (JEP 454, JDK 22) and the Class-File API is final (JEP 484, JDK 24); no `--enable-preview` flags are required.)*
* **Core Invariants:**
  * **Zero Runtime Heap Allocation:** $0	ext{ bytes}$ allocated during simulation `tick()` and query loops. This includes any runtime-generated marshaling bytecode.
  * **Target Throughput:** $1,000,000$ active entities @ $60+	ext{ FPS}$ ($< 16.6	ext{ ms}$ tick budget).
  * **Memory Storage:** Contiguous off-heap memory via `java.lang.foreign.MemorySegment`.
  * **Entity Handles:** Raw 64-bit primitive `long` types (`High 32 bits`: Index, `Low 32 bits`: Generation).
  * **Continuous Technical Documentation:** Every agent MUST generate and incrementally update `TECHNICAL_DOCUMENTATION.md` upon completing their phase, detailing architectural decisions, memory layouts, internal data flow, and usage examples.

## 1. Public API Contracts (Target DX)

### Component Definition & World Spawn
```java
// Component Data Definitions (Immutable Records)
public record Position(float x, float y) {}
public record Velocity(float dx, float dy) {}

// World Initialization & Entity Creation
World world = Hyperion.createWorld();

long entity = world.spawn()
    .add(new Position(0.0f, 0.0f))
    .add(new Velocity(1.0f, 1.0f))
    .id();
```

### System Registration & Execution Loop
```java
// Query System Registration
world.createSystem()
     .with(Position.class, Velocity.class)
     .each((long entityId, Position pos, Velocity vel) -> {
         pos.x += vel.dx;
         pos.y += vel.dy;
     });

// Zero-GC Update Loop
while (running) {
    world.tick();
}
```

### Relationship & Time-Travel Rewind API
```java
// Entity Graph Link
world.link(sourceEntity, Targeting.class, targetEntity);

// State Snapshotting & Frame Rewind
world.enableRewindBuffer(120); // 120-frame off-heap ring buffer
world.rewind(60);             // Instant hardware memory copy rewind
```

## 2. Low-Level Technical Requirements

1. **Storage Layout:** Archetype-based Struct-of-Arrays (SoA) layout. Component fields stored in contiguous off-heap primitive buffers managed by `java.lang.foreign.MemorySegment`.
2. **Query Engine:** $O(1)$ bitmask archetype matching via bitwise `AND` on 256-bit component bitmasks.
3. **Parallel Dispatcher:** Archetype query chunking mapped to `Executors.newVirtualThreadPerTaskExecutor()`.
4. **Relationship Indexing:** Composite 64-bit edge keys: `(RelationTypeID << 32) | TargetEntityID`.
5. **Snapshotting:** Direct native byte block copy (`MemorySegment.copyFrom()`) to capture snapshot frames in $O(N)$ contiguous memory write time.
6. **DX Marshaling Codegen:** The high-level component-marshaling layer MUST synthesize direct-access accessor/marshaling classes at runtime using the standard **`java.lang.classfile`** (Class-File API, final in JDK 24). Generated bytecode uses straight-line `getfield`/`putfield` against component views and primitive `invokevirtual` against the SoA cursor — eliminating reflection/`VarHandle` overhead so the ergonomic query DSL executes at direct-field speed ($\approx$ raw primitive access) with $0	ext{ bytes}$ heap allocation. No external bytecode libraries (ASM, ByteBuddy) are permitted; standard library only.

```
                                   ▼

```

### Agent 1: `Lead-Architect`
* **Role:** API Contract & Interface Signature Owner.
* **Outputs:** Interface definitions (`World.java`, `Query.java`), memory layout contracts, `ADR.md`, and initial `TECHNICAL_DOCUMENTATION.md` structure.
* **Guardrails:**
  * **No implementation logic:** Output Java interfaces, sealed contracts, and record signatures only.
  * **Immutable Signatures:** Signatures cannot be modified without an explicit ADR revision.

### Agent 2: `Perf-Core-Agent`
* **Role:** Low-Level Off-Heap Storage & Execution Engine Developer.
* **Outputs:** Archetype table storage, `MemorySegment` managers, bitmask indices, `tick()` loop, and update `TECHNICAL_DOCUMENTATION.md` with memory layout diagrams & buffer offset specifications.
* **Guardrails:**
  * **Strict Zero-GC Rule:** Absolute prohibition of `new` keyword, boxing (`Integer`), or heap arrays inside `tick()` and query loops.
  * **Primitive-Only Interfaces:** Use primitive `long`, `int`, and `float` variables for internal calls.

### Agent 3: `DX-Agent`
* **Role:** High-Level Ergonomics & Query DSL Engineer.
* **Outputs:** Record wrappers, query builders, graph relationship syntax, and update `TECHNICAL_DOCUMENTATION.md` with DSL usage guidelines and zero-cost abstractions details.
* **Guardrails:**
  * **$\le 3$ Lines:** Component definition and query setup must require 3 lines of code or fewer.
  * **Zero-Cost Abstractions:** High-level DSL methods must compile down to direct primitive method calls without allocation.

### Agent 4: `DevTools-Agent`
* **Role:** Telemetry & Rewind Buffer Engineer.
* **Outputs:** Off-heap snapshot ring buffer, TUI/WebSocket telemetry server, and update `TECHNICAL_DOCUMENTATION.md` with rewind mechanism and telemetry protocol specs.
* **Guardrails:**
  * **$< 2\%$ Overhead:** Telemetry hooks must introduce $< 2\%$ latency impact.
  * **Copy-Free Snapshots:** State snapshotting must use direct native `MemorySegment` block transfers.

### Agent 5: `QA-Bench-Agent`
* **Role:** Quality Gatekeeper & Profiler.
* **Outputs:** JMH benchmark suites, JFR allocation profiling logs, PR pass/fail flags, and append benchmark analysis to `TECHNICAL_DOCUMENTATION.md`.
* **Guardrails:**
  * **Fail-on-GC:** Automatically reject any code triggering heap allocations during simulation ticks.
  * **Throughput Gate:** Reject PRs failing to achieve $1,000,000$ entities processed @ $60+	ext{ FPS}$.
